# NACA Airfoil Characteristics

This project is an automated two-dimensional CFD workflow for generating a NACA 4-digit airfoil, creating a Gmsh mesh, running SU2 RANS cases, and plotting the resulting aerodynamic polar.

The current configuration analyzes a NACA 0012 airfoil at Mach 0.15 and Reynolds number 3,000,000. The default angle range is alpha = 0 to 5 degrees in 5-degree increments, so the default run evaluates alpha 0 and alpha 5.

## Workflow

`main.py` runs these stages in order:

1. Remove previous `workspace/run_alpha_*` directories.
2. Generate cosine-spaced NACA 4-digit coordinates in `geometry.py`.
3. Create a circular farfield domain and boundary-layer mesh in `meshing.py`.
4. Run one SU2 case per angle using a two-process pool in `simulation_parallel.py`.
5. Read the SU2 histories and average the final 100 samples in `postprocessing.py`.
6. Write the polar CSV and plot, including experimental data when `naca0012_exp.csv` is present.

## Requirements

- Python 3
- NumPy
- Matplotlib
- The Gmsh Python module
- SU2 with the `SU2_CFD` executable available on `PATH`

Install the Python dependencies with:

```bash
python3 -m pip install numpy matplotlib gmsh
```

The Gmsh executable alone is not sufficient: `meshing.py` imports and uses the Gmsh Python API.

## Running

Run the command from the repository root. The solver opens `template.cfg` using a relative path.

```bash
python3 main.py
```

For an SU2 installation that is not already on `PATH`, configure it before running, for example:

```bash
export PATH="/opt/SU2-v8.5.0/bin:$PATH"
python3 main.py
```

The main parameters are in `main.py`, including `naca_code`, Mach number, Reynolds number, angle limits, turbulence model, transition model, workspace directory, and mesh filename. Solver parameters and placeholder names are in `template.cfg`.

## Generated Files

All generated files are placed in `workspace/`:

| File | Description |
| --- | --- |
| `mesh.su2` | SU2 mesh generated by Gmsh |
| `mesh_report.txt` | Mesh node, element, and `minSICN` quality statistics |
| `mesh_preview_wsl.png` | Mesh point preview |
| `run_alpha_XX/config.cfg` | SU2 configuration for one angle of attack |
| `run_alpha_XX/su2.log` | SU2 console output |
| `run_alpha_XX/history.csv` | Iteration history and aerodynamic coefficients |
| `run_alpha_XX/surface_flow.csv` | Surface solution output |
| `run_alpha_XX/flow.vtu` | ParaView volume output, when produced by SU2 |
| `run_alpha_XX/restart_flow.dat` | SU2 restart data |
| `polar_data.csv` | Averaged `Alpha`, `Cd`, and `Cl` values |
| `polar_plot.png` | `Cl` versus `Cd` polar plot |

The `workspace/` directory is ignored by Git because these files are generated artifacts. Existing angle-run directories are deleted each time `main.py` starts.

## Geometry and Mesh

`geometry.py` accepts a four-character NACA code, such as `0012`, and returns upper and lower surface coordinates using cosine spacing. The generated profile uses the standard NACA thickness equation with a finite trailing-edge coefficient (`-0.1015`).

`meshing.py` creates:

- A circular farfield with radius 15 chord lengths.
- Physical boundaries named `airfoil` and `farfield`, plus the `fluid` surface.
- A wake refinement box behind the trailing edge.
- A boundary layer around the airfoil and trailing-edge arc, with first size `1e-5` and thickness `0.03`.
- A mesh quality report based on the `minSICN` metric.

## SU2 Configuration

`template.cfg` is populated for each angle by replacing these placeholders:

```text
%TURB_MODEL%  %TRANS_MODEL%  %MACH%  %AOA%
%REYNOLDS%    %INPUT_MESH%   %RESTART%
```

The default solver setup is direct RANS with the SST turbulence model and LM transition model, Roe flux, MUSCL reconstruction, Venkatakrishnan limiting, adaptive CFL, up to 2,000 inner iterations, and a residual target of `-8`. Cases are cold-started because the runner sets `RESTART_SOL= NO`.

## Results and Experimental Comparison

`postprocessing.py` skips an angle when its `history.csv` is missing and continues with the remaining cases. It averages the last 100 rows, or all rows if fewer than 100 are available. If no valid history is found, no polar is written.

When `naca0012_exp.csv` exists in the repository root, its `CL` and `CD` columns are added to `polar_plot.png` as an experimental comparison for Reynolds number 3,000,000. The file is not used by the solver.

## Validation Without Running CFD

To check Python syntax without launching Gmsh or SU2:

```bash
python3 -m py_compile geometry.py meshing.py simulation.py simulation_parallel.py meshing_old.py postprocessing.py main.py
```

## Implementation Notes

- `simulation_parallel.py` is the active SU2 runner imported by `main.py`; it uses two concurrent worker processes.
- `simulation.py` is an older serial runner and is not imported by the main workflow.
- `meshing_old.py` is an older mesh-generation implementation and is not imported by the main workflow.
- Worker failures are logged in the corresponding `su2.log`, while postprocessing can produce a partial polar if other cases succeed.
- The angle step must be positive and compatible with the configured start and end values.
- The geometry routine is intended for four-character numeric NACA codes. Symmetric NACA 00xx profiles are the currently verified use case.
